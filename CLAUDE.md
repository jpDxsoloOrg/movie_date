# CLAUDE.md

Guide for AI assistants working on Movie Date. A room of people swipe through titles,
and everyone agreeing on one is a match. Live at https://d19oka7lgeykfv.cloudfront.net.

The site replaced a Flutter + Supabase mobile app, which is gone from this branch and
stays in git history.

## Stack

- npm workspaces, TypeScript throughout, Node 22
- Frontend: React 18, Vite 5, react-router-dom 6, installable PWA (`vite-plugin-pwa`)
- API: AppSync GraphQL with one Lambda resolver. `graphql/schema.graphql` is the contract
- Data: one DynamoDB table, S3 for avatars, a private S3 bucket for the Plex index
- Auth: Cognito user pool, email as username, SRP from `amazon-cognito-identity-js`
- Infrastructure: SST (`sst` 4.17.1 pinned) in `sst.config.ts`, AWS `us-east-1`, stage `production`
- Titles from TMDB, streaming availability from RapidAPI. Their keys are SSM SecureStrings
  under `/movie-date/<stage>/`, read by the Lambda, and never reach the browser or the repo

## Layout

```
graphql/schema.graphql     API contract
sst.config.ts              All infrastructure, including resolver wiring and the CSP

packages/
  core/                    Types and rules shared by frontend and functions
  functions/src/
    resolver.ts            Routes each GraphQL field to a handler
    handlers/              One file per field
    lib/                   Keys, DynamoDB, TMDB, Plex Request, limits, matching
    plexIndexJob.ts        Cron job that builds the Plex index, every 6 hours
    preSignUp.ts, postConfirmation.ts    Cognito triggers
  frontend/src/
    AppRoutes.tsx          Routes
    screens/               One component and CSS file per screen
    components/            Primitives, plus deck/, filters/, match/ and room/
    mode/                  Mode rules, paths and copy
    services/api.ts        Every GraphQL operation
    styles/                tokens.css and themes.css
    gql/                   Generated by codegen: don't edit
  test/                    vitest, mirroring the packages above, plus contract/ and infra/
```

`packages/frontend/README.md` is the briefing for building a screen, and
`docs/DESIGN_NOTES.md` has the look and the primitives. Read both before UI work.

## Commands

Run these from the repo root.

```bash
npm test             # all suites
npm run typecheck
npm run build        # frontend
AWS_PROFILE=league-szn npx sst deploy --stage production
```

- Always run tests with `npm test` from the root. `vitest --root` gives false failures.
- CI runs on pull requests only: typecheck, infrastructure typecheck, tests and build. It
  doesn't deploy. To typecheck `sst.config.ts` yourself, run `npx sst install --stage production`
  and then `npx tsc -p packages/test/infra/tsconfig.json`.
- After changing the schema or an operation, run `npm run codegen -w @movie-date/frontend`.
- For local UI work, run `npm run dev -w @movie-date/frontend`. It needs `VITE_GRAPHQL_URL`,
  `VITE_USER_POOL_ID` and `VITE_USER_POOL_CLIENT_ID` in `packages/frontend/.env.local`, and
  optionally `VITE_GRAPHQL_REALTIME_URL`. There is no local backend, so these point at a deployed stage.

### Live end-to-end run

```bash
AWS_PROFILE=league-szn PLAYWRIGHT_MODULE=/path/to/node_modules/playwright node scripts/e2e-live.mjs
```

Playwright isn't a dependency here, so `PLAYWRIGHT_MODULE` points at an install whose
browser is present. The run uses real Cognito, AppSync, TMDB and the streaming API, and
creates a temporary user in Plex Request's real pool. It deletes what it creates. If a run
is killed, recover with `node scripts/e2e-live.mjs --cleanup <E2E_OUT>/state.json`.
`E2E_ONLY` runs a subset, but only a full run counts.

## Data model

One table, `pk`/`sk`, with TTL on `expiresAt`. Build keys with `packages/functions/src/lib/keys.ts`,
never inline.

| pk | sk | Holds |
|---|---|---|
| `USER#<sub>` | `PROFILE` | Profile, current room, Plex link |
| `USER#<sub>` | `PLEX_LINK`, `PLEX_LINK_COOLDOWN` | Pending emailed code, send limit |
| `USER#<sub>` | `LIMIT#<name>#<window>` | Per-user limits |
| `ROOM#<id>` | `META` | Code, `filters`, `tvFilters`, threshold, `round`, `tvRound` |
| `ROOM#<id>` | `MEMBER#<sub>` | Membership |
| `ROOM#<id>` | `SWIPE#<round>#<sub>#<media>` | Direction and title snapshot |
| `ROOM#<id>` | `TALLY#<round>#<media>` | Atomic `likes` and title snapshot |
| `ROOM#<id>` | `MATCH#<matchedAt>#<media>` | A match, newest first on a reverse query |
| `ROOM#<id>` | `MATCHED#<round>#<media>` | Sentinel that makes a match exactly-once. `clearedAt` stops it being announced |
| `CODE#<code>` | `ROOM` | Room code lookup |
| `CACHE#<kind>#<key>` | `CACHE` | TMDB and streaming cache |
| `LIMIT#<name>` | `<window>` | Global limits |
| `PLEX#INDEX` | `LEASE` | The index job's lease, the only row it may touch |

`<media>` is `movie:<id>` or `tv:<id>`, because TMDB numbers movies and shows separately.
Rows written before shows existed have a bare id, and `parseMediaKey` reads those as movies.
Never pick a mode from a `movie:` prefix: use `mediaRefOfSk`. `round` and `tvRound` are
separate counters that overlap, so filter a round's rows with `inMode`.
Decision 7 in `docs/DECISIONS_FOR_REVIEW.md` covers what the bare rows still affect.

## Keeping likes private

Nobody learns what anyone else liked until there's a match. Likes must never reach a client
or change a deck's contents or order: see decision 83. `pendingMatch` skips cleared matches
and matches made before the caller joined (decisions 84 and 85).

## Two modes

Movies and Going Steady (TV shows) are modes of one app, sharing the account, room, members
and threshold. Each has its own deck, filters, swipes, matches and round.

- The URL decides the mode wherever it can: `/shows*` is Going Steady; `/`, `/filters*` and
  `/match/*` are Movies. The exception is a plain `/` for someone in Going Steady, which
  redirects to `/shows` unless the link carries `MOVIES_STATE` (decision 44). History, Members, Profile and Settings are shared and keep the last
  mode, which the device remembers. See `mode/modeRoutes.ts`, and use its helpers for every
  link into a deck, filters or a match.
- `public/mode-boot.js` repeats the path rules so `/shows` gets its theme before the app
  loads. A test pins the two copies together.
- Mode wording lives in `mode/modeCopy.ts`. A show string must not name a movie.
- A card's `movie` is always set, and in Going Steady it's a show in Movie's shape, so
  `movie.id` can be a TV id. The id has to travel with `mediaType`.

## Theme tokens

- `styles/themes.css` holds every mode colour as a `--theme-*` variable, under `:root,
  [data-theme="movies"]` and `[data-theme="shows"]`. Each theme must define the same
  variables and pass the contrast pairs in `packages/test/frontend/src/styles/themes.test.ts`.
- `styles/tokens.css` aliases those as `--color-*` and holds spacing, type and sizes.
  Screens use `--color-*` and never a raw colour.
- Movies is coral to amber with an orange accent. Going Steady is indigo to teal with a teal
  accent. Pages off the gradient are dark in both.
- Text never sits straight on the gradient. It sits on `--theme-scrim`.
- Breakpoints are literal: tablet from 640px, desktop from 1024px.

## Plex Request integration

Plex Request is a separate app (`~/source/plex_request`) with live users. Movie Date calls
its private Lambda, `plex-request-api-devtest-integration`, directly with `lambda:InvokeFunction`.
That name is pinned in `sst.config.ts`, and that IAM grant is the only access control.

- The ops are `findUser`, `libraryMovies`, `libraryShows`, `movieStatus`, `showStatus` and `createRequest`,
  all in `packages/functions/src/lib/plexRequest.ts`. `createRequest` makes a single attempt,
  because a retry could start a second download for a trusted user.
- People link their account with a code emailed through SES. The code is the only proof of
  ownership, since sign-up doesn't verify an email.
- `plexIndexJob` reads the library every 6 hours and writes the index to the private bucket.
  Run it by hand with `aws lambda invoke` on the `plexIndexFunction` output.
- Movies keep TMDB ids. Plex Request keeps shows by TVDB id, and the job converts them.
- Plex status, the Plex filter and Request on Plex work in both modes. A show request sends its
  TVDB id, never `tmdbId`, and optional `seasons`. A show's id sent to `requestOnPlex` without
  `mediaType` would request the movie with that number, so never send one, in a script or a test.

### Deploying Plex Request

Deploy it from its `main` branch with its own commands, not from a feature branch, and only
with the owner's approval. `sst deploy` here doesn't touch it.

The caveat is its environment. Radarr and Sonarr keys live in its settings table, and
`serverless.yml` defaults the `*_API_KEY` variables to empty strings, though the `*_BASE_URL`
variables have real defaults. Those variables are the fallback for a settings row with no
URL or key, so a deploy from an empty environment removes that fallback. Before deploying, check what an empty environment would change,
and confirm the settings rows hold both values.

## Conventions

- No `any`. Functional components, async/await, and comments that explain why rather than what.
- Plain CSS, one file per component, using tokens. No CSS modules or Tailwind.
- No inline styles except values computed per frame. The CSP's `style-src 'self'` blocks them in production.
- GraphQL operations belong in `services/api.ts`, not in screens.
- Handlers take the user from `identity.sub`, never from arguments, and look the room up
  from the caller's profile.
- A new schema field needs a resolver. `sst.config.ts` adds them from the schema, and
  `packages/test/infra/stack.test.ts` checks the result.
- Tests live in `packages/test`, mirroring the source tree.
- Don't add Co-Authored-By lines to commits.
- Never put secret values in the repo, docs or logs.
