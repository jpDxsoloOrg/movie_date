# Decisions for review

Choices made while the owner was away. Each one can be changed; tell Claude which.

| # | Question | Chosen | Alternative | Why |
|---|---|---|---|---|
| 1 | Going Steady color scheme | Cool indigo to teal gradient with a teal accent | Plum to pink, or deep green | Clearest contrast with the warm coral and amber movie theme, and reads as "evening in" |
| 2 | Should the Sonarr lookup fix in Plex Request be deployed? | Open it as a separate PR and leave it undeployed. Request on Plex stays off for shows until it's live | Deploy it overnight | Approval to deploy covered one private function. This changes how live requests are approved for 11 users, so it should get the owner's review |
| 3 | Daily Plex request limit | 10 per user per day | No limit, or a different number | Stops a swipe app triggering a run of downloads |
| 4 | RapidAPI spend limits | 50 lookups per user and 500 overall per day, then fall back to TMDB | Limits matched to your RapidAPI plan | Open sign-up could otherwise burn paid quota; these numbers are guesses |
| 5 | Abuse limits | 10 wrong room codes per hour, 20 avatar uploads per day | Other numbers | Blocks guessing and storage abuse without touching normal use |
| 6 | Live "about N movies" count: `totalResults` on `DeckPage`, or a separate query? | Separate `filterPreview(filters)` query returning `totalResults` (null when unknown) and `posterUrls` for the preview strip | `totalResults` on `DeckPage` | `deck` only reads saved filters, so it can't count a draft before Apply |
| 7 | Rewrite existing swipe, tally and match rows to `movie:<id>`? | No migration. Old rows still read as movies, but a swipe made before the deploy can't be undone and its tally starts over | Backfill script before deploying | The spec says there are no real users yet; only test data is affected |
| 8 | `type` of the Plex entry in `watchOptions` | New value `library` | Reuse `subscription` | It isn't a paid service, and the frontend can give it its own label |
| 9 | Extra cap on Plex link emails | 10 per user per day, on top of the spec's one a minute | Only one a minute | Sign-up doesn't prove an email, so the code is the only ownership check. One a minute would allow 7,200 guesses a day and steady mail to the real owner |
| 10 | `startPlexLink` while Plex Request is down | Fails with "Plex Request is unavailable right now" and allows an immediate retry | Answer `sent: true` anyway | An outage says nothing about who has an account, and `sent` would leave people waiting for mail that never comes |
| 11 | Do non-English titles count in the Plex deck? | Yes. The English-only rule stays on TMDB results | Add language to the index and filter | It's the owner's own library, and the spec's index record has no language |
| 12 | Light or dark for pages off the gradient? | Warm dark brown everywhere, with the gradient kept behind the deck and match screens | Stay light, with a cream page | "Warm movie night", and posters glow on dark. It also suits Going Steady's "lights go down". Screens only use tokens, so a light palette is a change to `themes.css` |
| 13 | Tablet navigation (640 to 1023px) | A rail with five destinations, and the rest in the drawer behind More | Keep the phone's app bar and bottom nav | The spec leaves it open. A rail also leaves the deck its full height on a phone in landscape, where the bars would take a third of it |
| 14 | Where the auth collage's posters come from | 24 fixed TMDB image URLs, in `PosterCollage.tsx` | An unauthenticated API for trending posters | Signed-out visitors can't call the API, and a public endpoint is a lot for a backdrop. A dead URL just leaves a tinted tile |
| 15 | Auth screen copy | Added "Pick the movie before the popcorn gets cold." and a line under it, on desktop | No headline | The spec asks for tidier screens but gives no copy. It's easy to reword in `AuthLayout.tsx` |
| 16 | Should the installed app stay locked to portrait? | No: manifest `orientation` is now `any` | Keep `portrait` | Portrait would pin an installed tablet and desktop app away from the layouts this build adds |
| 17 | Should the from/to range be year boxes or something finer? | Decade chips that join into a span, year boxes, and plain dates behind Exact dates | A two-thumb timeline slider | Year lists can't hold a half-typed value or overflow on iOS, and a slider is fiddly on a phone |
| 18 | What does the phone's Filters sheet do on close? | Goes Home and drops unapplied edits, with no prompt | Prompt, or keep the draft for reopening | That's what leaving the old page did, and `RoomProvider` clears drafts off `/filters`, so keeping one needs a change there |
| 19 | Keep `/filters/actors` now that search is inline? | Yes, behind a Full actor search link | Remove the route | The spec says to keep every route, and it still has its unsaved prompt |
| 20 | Can someone enter a Plex code without sending a new email? | Yes: an I Have a Code button sits beside Email Me a Code | Only show the code box after sending | Fetching the mail can reload the page on a phone. With the box gone, they'd have to send again, and a send inside the minute mails nothing |
| 21 | When is the invite QR code on show in Room Members? | Always from 640px, and behind Show QR Code on phones | Behind the button at every width | On a bigger screen the point is to scan it with a phone. On a phone the code would push the member list off the screen |
| 22 | Does the desktop details panel look up every card it shows? | Only once a card has been on top for 450ms, so skipped cards cost nothing | Look up every card, or put Where to Watch behind a tap | The spec wants it without a tap, but each lookup can draw on the RapidAPI limits in decision 4. A steady swiper can still reach 50 a day, then falls back to TMDB |
| 23 | Should the panel's trailer autoplay? | No: a Play Trailer button over the backdrop | Autoplay on each new card | Sound starting on every swipe would be unbearable. The tap-opened sheet still autoplays |
| 24 | What does clicking a card do on desktop? | Nothing, and there's no info button; dragging, buttons and keys all still work | Keep opening the sheet | The panel already shows the same details, so a sheet would only cover them |
| 25 | Where does Home's third part go from 1024 to 1199px? | Deck, then one scrolling column with details above the room panel. Three columns start at 1200px | Three columns from 1024px | At 1024px three columns leave the poster under 300px wide |
| 26 | Tablet Home (640 to 1023px) | Deck and room panel, with details staying in the sheet | Add a details panel too | There's no room for a readable third part beside a poster |
| 27 | How does the Plex tile in Where to Watch read, given it has no deep link? | A plain tile, listed first, with a chevron on a black plate and the label "Library" | A "Watch on Plex" link to the Plex web app | The spec says there's no deep link, so a tile that looks pressable would promise something it can't do |
| 28 | What does the Request on Plex confirmation say and do? | "Request Heat?", saying a trusted account's download starts straight away, with Cancel and Request. A failure closes it and shows a toast | Keep it open and show the error inside | The warning is why the spec asks for a confirm. The toast is how the rest of the site reports errors, and the limit message needs no retry there |
| 29 | How should History look on desktop? | A poster wall of ticket stubs, with the newest match drawn double width over its backdrop as "Latest match" | A uniform grid, or the phone list in columns | The spec wants a real desktop layout, and the newest match is the one people come back for |
| 30 | Should History's tabs move to `SegmentedControl`? | No: real tabs and tab panels, styled to match it | Use the primitive, which is a radio group | They switch panels that stay mounted, so tab semantics are correct, and it keeps the existing tests' intent |
| 31 | What does the live "about N movies" count include? | TMDB's `total_results`, plus Plex matches when both are on, with overlaps counted twice | Estimate how many pass the deck's English-only rule, or count pages by hand | The spec asks for TMDB's total where it allows. The deck drops non-English titles after discovery, so the count can run high, which "about" covers |
| 32 | What should Filters say in a room that has never saved filters? | Keep the spec's Apply default and say so: "The deck has every movie for now. Apply with nothing picked narrows it to this year's." The count and This year chip keep showing what Apply would deal | Show the live deck (All time) until something is touched, or stop defaulting to this year | REWRITE_SPEC says saving fills in Jan 1, and the count is defined as what Apply saves. Changing either changes behaviour rather than wording, so that's the owner's call |
| 33 | How does the live count read past TMDB's ceiling? | "20,000+ movies" for anything at 20,000 or above, including Plex added on top | Hide the count, or keep "About 20,001" | TMDB's `total_results` stops at exactly 20,001 (checked directly: 1,001 pages), so a higher figure is a floor, not an estimate. The count can't move between broad filters; only a narrower pick shows a change |
| 34 | Where do phone toasts go on routes with no bottom nav? | Under the app bar | Drop the nav offset and keep them at the foot | Tried on paper first: at the foot, a toast lands right on Leave Room in a one-member room (y 784-832 against 799-843). Where the page ends depends on its length, so no bottom offset is safe |
| 35 | Details panel order | Facts, Where to Watch, Plex status, then the full overview | Clamp the overview on short screens | There's no sheet on desktop (decision 24), so a clamped overview could never be read in full. Moving it down keeps every word, a scroll away |
| 36 | Should the integration Lambda get a resource policy? | No. It stays limited by IAM on the caller's side, which the spec allows | Add an Allow statement naming Movie Date's role | Lambda policies only add Allow statements, and in the same account an identity policy is enough by itself. It wouldn't stop any other principal, so it would look like protection without being any. Real isolation needs a separate account or an SCP |
| 37 | How does the e2e script avoid bouncing link code mail? | The linking actor signs up with `success+<id>@simulator.amazonses.com`, SES's mailbox simulator | Keep example.com and clear the suppression list after each run | Nothing bounces, so nothing is forwarded to noreply@jpdxsolo.com or added to the suppression list. That removes the question rather than cleaning up after it |
